[ how_the_ramp_works ]

One space, four marks, no grey

The ramp is a space, then ., :, * and #. The jumps between them are wide, so a value between two slots is rounded, never blended. At 40–80 columns those jumps still draw an edge. A sixty-eight step ramp at the same width puts consecutive glyphs too close together, and the picture turns to speckle.

Raise contrast until the subject separates from the background, and switch invert on when the subject is light on a dark field. All five characters are 7-bit ASCII. The other five ramps are listed on the home page.

Where minimal ASCII excels

$ narrow columns

Ideal between 40 and 80 columns. While longer ramps need width to avoid speckling, 5 sparse characters hold clear geometry inside narrow windows or mobile feeds.

$ code comments

Because there are no heavy ink blocks, minimal art integrates cleanly into source code docstrings, git commit trailers, and terminal splash banners without distracting.

$ contrast tuning

Increase contrast by +20 to +40 to decisively bin image pixels into either empty paper or structured hash lines, sharpening your visual icon.

[ faq ]

Minimal ramp questions

Why use only 5 characters for ASCII conversion?

The minimal ramp ( .:*#) is optimized for compact sizes between 40 and 80 columns. At small dimensions, subtle gradients break down, but five widely spaced steps preserve immediate recognizable shapes.

How does the minimal ramp compare to the block charset?

Both use five steps, but minimal uses classic 7-bit ASCII punctuation rather than solid Unicode tiles, making it feel like an airy wireframe sketch that never clutters code comments.

What contrast setting is recommended for the minimal ramp?

Increase contrast by +20 to +40 to firmly push background pixels into empty space and foreground subjects into asterisk and hash marks.
